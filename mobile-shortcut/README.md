# 存入 Shelf（自配置）

使用配套已签名 .shortcut 文件。AirDrop 到 iPhone，点“添加快捷指令”。从微信原文件或“文件”App 分享一个文件，选择“存入 Shelf（自配置）”；首次输入自己的 HTTPS 服务根地址，再登录与电脑相同的 Google 账号。

此版本使用独立的 Shelf-Selfhost-config-v1.txt 和 Shelf-Selfhost-session-v1.txt，不覆盖原官方快捷指令缓存。会话包含绑定的服务地址和令牌，不保存 Google 密码；不应分享缓存文件。更换服务器时在快捷指令文件夹删除这两个自配置缓存文件后重新运行，原官方缓存无需更改。

保留原文件名和字节，文件直接以原始流发送；服务分块加密后写 Google Drive，不通过 Base64 把大文件整体扩张。成功前核对最终记录的 id、name、size、SHA-256。系统中断不显示成功。微信聊天记录仅在可识别的一个附件/纯文字时提取，否则提示打开原文件。

Mac 已通过官方 shortcuts sign 签名和导入，静态检查动作输出、条件与原始上传路径。服务器模拟覆盖0字节、8 MiB及65 MiB、中文文件名、短读/超长/破坏哈希/中断。新服务器地址/缓存流程未在实体 iPhone 或真实 Google 项目中运行；手机后台执行仍受 iOS 管理，大文件保持快捷指令前台。


## 2026-10-14 短信文字修复

“信息”分享的 RTFD、多信息文本及直接分享的纯文字，先用苹果原生“从输入中获取文本”转换成纯文字，再按 kind:text 存为 Shelf 文字卡片。保留中文、换行和链接，空内容停止，不把 RTFD 包当作文件上传。PDF、图片及普通文本文件继续保留原文件与字节；该转换只用于原生文字和 RTFD 输入。已生成官方“存入 Shelf”和自配置“存入 Shelf（自配置）”两份，各自沿用原缓存路径。

本地生成动作图的输入测试覆盖 RTFD、原生富文本/纯文字、空内容和原文件分支。Mac 的原生快捷指令命令行检查未在限定时间内返回，已停止该独立检查；不将动作图模拟当作实体 iPhone 信息分享测试。2026-10-14 用户已在实体 iPhone 从“信息”分享，并确认官方签名修复版显示为文字卡片；自配置版的新服务器授权仍需独立实测。两份签名修复文件均已在 Mac 快捷指令中导入。
